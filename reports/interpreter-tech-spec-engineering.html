本地实时同传系统 · 工程技术规格（详版）

面向工程师 FastAPI · WebSocket MLX-Whisper Ollama qwen2.5:3b Apple Silicon / M4

本文档穷尽式列出实时语音同传管线的实现细节：音频分帧、VAD、说话人聚类、流式 ASR 端点算法、解码超参、分句合并、翻译路由、LLM 引擎、WebSocket 事件协议、全部配置项、延迟预算与调优实验。所有数值均取自当前代码库（backend/）。

1 · 系统概述与设计原则

系统是一个伪流式（pseudo-streaming）双向语音同传服务：客户端以 20ms 帧推送 16kHz 单声道 PCM，服务端做 VAD 端点检测→缓冲区整段重解码（Whisper）→分句合并→本地 LLM 翻译→WebSocket 广播事件到眼镜 HUD。中英双向。

设计原则

  • 全本地：ASR（MLX-Whisper，Apple GPU/Metal）与 MT（Ollama 本地 LLM）均在设备内运行，无云端、无网络依赖、零按次成本。
  • 准确优先：句尾对完整缓冲区做一次正规解码（不复用半截 partial），保证转写完整与断句自然；低延迟为可选模式。
  • 无状态翻译单元：每个提交句独立翻译，不注入上一句译文，避免小模型跨句污染/复读。
  • 确定性输出：翻译 temperature=0；中文统一 OpenCC 繁→简。
  • 可降级：webrtcvad 缺失时回退能量门限；ASR/MT 后端可切换。

3 · 端到端数据流

  1. 客户端 POST /session/start {target_lang} → 得到 session_id。
  2. 打开 WS /ws_audio/{session_id}；服务端回 audio_connected（声明 16kHz / s16le / mono / 20ms）。
  3. 客户端持续发送二进制 PCM 帧（每帧 640 字节 = 320 样本 × 2）。
  4. process_audio_chunk → RealtimeAudioPipeline.push_chunk（在线程池）：切 20ms 帧 → 每 frames_per_batch=25 帧（=500ms）成一个批 → 批级 VAD/能量判定 → 说话人分配 → 推入该说话人的流式 ASR。
  5. ASR 达到解码条件时解码缓冲区：非最终结果 → 广播 partial_transcript（仅显示，不提交）；最终结果（端点静音触发）→ 进入合并层。
  6. prepare_utterance：LID 平滑、说话人窗口、发 transcript 事件，累积 pending，满足 flush 条件则产出待译文本。
  7. 待译文本经 asyncio.create_task(_translate_and_broadcast) → translation_router → 引擎（Ollama）→ 广播 translation 事件。
  8. 客户端把 partial_transcript/transcript/translation 渲染成滚动字幕。

5 · VAD 与说话人聚类

5.1 语音活动判定（批级）

每 500ms 批计算两路特征并取「或」：

vad_prob  = voiced_frames / total_frames   # webrtcvad.Vad(1)，逐 20ms 帧
energy    = sqrt(mean(x^2))                # 归一化到 [-1,1] 的 RMS
is_speech = vad_prob >= 0.12 or energy >= 0.0012
常量值含义
webrtcvad 侵略度Vad(1)0–3，1 偏宽松
AUDIO_VOICED_RATIO_THRESHOLD0.12批内浊音帧占比阈值
AUDIO_ENERGY_THRESHOLD0.0012RMS 能量兜底阈值

静音批会给所有有未决音频的说话人推入等长静音帧，用于累积 trailing silence 触发各自端点。

5.2 轻量说话人区分

无需外部模型的近似 diarization：对每个语音批做 8 维频谱指纹并做余弦聚类。

# _SpeakerTracker
spectrum = |rfft(signal)|
feats    = log1p(mean over 8 频带)     # 8 维
feats    = feats / ||feats||           # L2 归一
score    = cosine(feats, prototype)
if score < 0.82 and n_speakers < 3:  新建说话人 A/B/C
else: prototype = 0.85*prototype + 0.15*feats  # 动量更新
常量值
match_threshold0.82
momentum0.85
MAX_SPEAKERS / 标签3 / A,B,C

6 · 流式 ASR 端点算法

每个说话人维护一个流式 ASR 实例，内部按帧累积缓冲并周期性重解码整段（伪流式）。核心状态与判定：

# 每帧 push_frame 后
buffered_audio_ms        += frame_ms
buffered_since_decode_ms += frame_ms
trailing_silence_ms       = 0 if 语音帧 else += frame_ms

should_finalize = (buffered_audio_ms >= MIN_COMMIT(300)
                   and trailing_silence_ms >= COMMIT_SILENCE(300))
                  or buffered_audio_ms >= MAX_SEGMENT(4000)

should_decode   = should_finalize
                  or buffered_since_decode_ms >= DECODE_INTERVAL(500)
参数值作用
ASR_BATCH_MS（解码间隔）500partial 重解码周期
ASR_COMMIT_SILENCE_MS300句尾静音阈值（区分句内停顿 vs 句尾）
ASR_MIN_COMMIT_MS300最短可提交音频，挡碎片/短幻觉
ASR_MAX_SEGMENT_MS4000强制断句上限（防跑飞）
ASR_REUSE_PARTIAL_AS_FINAL0（关）fast-path：见下

去抖与稳定度

  • 签名去重：(text, is_final) 与上次相同则丢弃，避免重复事件。
  • stability：与上次 tokens 的最长公共前缀比例，用于前端标示 partial 稳定度；final 恒为 1.0。
fast-path（默认关闭，ASR_REUSE_PARTIAL_AS_FINAL=0）
当句尾自解码后无新语音时，可把最近的 partial 直接升格为 final，省掉一次整段重解码（约 200–400ms）。但它可能把「说话中途解码的半截结果」当成最终结果 → 转写截断、断句奇怪。因此默认关闭，句尾一律对完整缓冲区正规解码。置 1 进入低延迟模式。

7.2 混合模型路由（仅 mlx）

按会话目标语反推源语选择模型（ASR_HYBRID_BY_TARGET=1）：

use_fast = target_lang in {"zh"}          # 目标中文 ⇒ 源为英文
model    = "whisper-small.en-mlx" if use_fast else "whisper-small-mlx"
lang     = "en"                  if use_fast else ASR_LANGUAGE_HINT

英译中走 English-only 模型（数字/术语更准）；中译英走多语模型保中文识别。

7.3 后处理

  • OpenCC 繁→简：to_simplified() 施加于所有 ASR 文本（Whisper 偶出繁体）。
  • 幻觉过滤：final 段若归一化后 ≤16 字且命中已知幻觉短语集（"Thank you"/"谢谢观看"/"请点赞订阅"…）则丢弃。仅对极短段生效，正常内容永不误删。

8 · 分句合并与提交层

ASR final 段进入 prepare_utterance：先发 transcript 事件，再把文本累加到 pending_text，按下列任一条件 flush 为「待译句」。

flush if len(pending) >= MERGE_FORCE_CHARS(60)
   or pending.endswith(句末标点 . ! ? ; : 。 ！ ？ ； ：)
   or len(latest_segment) >= MERGE_SHORT_MAX_CHARS(24)
   or (now - pending_started) >= MERGE_MAX_WAIT_SECONDS(0.15)

音频路径对 final 段以 force_commit=True 调用，因此通常立即 flush；merge 窗口 0.15s 仅用于把紧邻的碎片并入同句、控制尾延迟。拼接时按需补空格（下一段以标点开头则不补）。

语种判定平滑（LID）

LID_SMOOTH_WINDOW5近 5 次观测多数表决
LID_MIN_CONFIDENCE0.65低于此置信的观测不计入

避免逐句语种抖动导致翻译方向反复横跳；稳定语种缓存在 speaker.stable_source_lang。

9 · 翻译路由

translate_with_manager_detailed() 先 gate 决策 + write-plan，再按优先级出译文，返回 route 名以便观测：

  1. 精确缓存 / 术语表命中 → manager_glossary（~0ms）。
  2. legacy 路由（精确缓存 + 模糊 TM + TM 润色）→ manager_router:*。
  3. 管理引擎（LLM） → manager_ollama / manager_student-editor。
  4. 异常兜底 → manager_fallback_error（回落原文）。

TM 润色开关 / 阈值on / 0.85

  • 术语占位：PRESERVE_TERMS=("ai agent",) 先替换为 [[TERM_0]]，译后还原，防止被翻译/大小写破坏。

13 · 延迟预算与调优实验

M4 上的组件耗时（实测）

组件英文中文
Whisper small 解码~200 ms~360 ms
Whisper medium 解码~580 ms~1050 ms
Whisper large-v3-turbo 解码~800 ms~1560 ms
qwen2.5:3b 翻译（热）~300–500 ms

端到端尾延迟（说完 → 出译文，含结束静音）

配置英译中中译英准确/断句
fast-path 关 · VAD 500 · commit 300 · merge 0.15（当前）1.41 s2.00 s准确、断句正常
细 VAD 120 + commit 300—2.22 s碎裂、更差
merge 0.4（旧）~1.6 s~2.3 s正常
关键结论
断句检测是物理下限：必须先听到 ≥300ms 静音才能确认句子结束。细颗粒 VAD 会把句内停顿误判为句尾（碎裂），反而增加尾延迟。500ms 粗批靠「看不见短停顿」保护断句。
「准确 + 自然断句」的现实尾延迟约 1.4–2.0s；要压到 0.5–0.8s 只能开 fast-path（牺牲部分准确度/偶发截断）。二者不可兼得。

14 · 基准方法与结果

backend/benchmarks_e2e/e2e_benchmark.py：通过真实 WS 路径流式推送合成语音（TTS，7 句），按真实节奏发帧 + 1600ms 结束静音，端到端测：

  • WER（英，词级）/ CER（中，字级）：参考 vs Whisper 输出（Levenshtein）。
  • chrF：字符 n-gram F 值（参考 vs 译文）；可选 LLM-as-judge（qwen3:8b，0–100 语义分）。
  • 尾延迟：最后一帧音频 → final translation 事件。
指标结果
ASR 错误率（均值，WER/CER）≈0.089（清晰语音近逐字）
翻译 chrF（整体 / 中译英）63 / 89
尾延迟 均值 / p951.66 s / 2.28 s

chrF 对中文短句合理意译偏严格（英译中偏低不代表译文差）；建议辅以 LLM-judge 或人工判读。

16 · 已知限制与路线

限制 / 失败模式

  • 尾延迟下限 ~1.4–2.0s（准确模式），受端点静音 + 整段解码 + LLM 串行约束。
  • 说话人区分为 8 维频谱近似，嘈杂/相似音色下不稳；非生产级 diarization。
  • Whisper 短段幻觉：靠短语黑名单 + min_commit 兜底，非语义级。
  • 16GB 内存限制更大模型（medium/turbo/7B）常驻。
  • 伪流式重解码在极长句（>4s）会被 MAX_SEGMENT 强切。

路线

  • 近期：识别-翻译流水并行；端上更小/更快 LLM；更快端点（自适应静音阈值）。
  • 中期：多语种（日/韩/西）；专业术语词库；生产级说话人分离。
  • 远期：定制 AR 眼镜形态；专用低功耗推理芯片；全天候续航。
